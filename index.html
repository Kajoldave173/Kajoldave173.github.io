PROJECT_01 FEATURED

Customer lifetime value prediction & segmentation engine

A hybrid probabilistic-ML pipeline on 1M+ e-commerce transactions that halved CLV prediction error, deployed with drift monitoring, automated testing, and an interactive scoring dashboard.

THE PROBLEM

Most CLV models pick one lane: either a probabilistic approach like BG/NBD that captures the underlying buying process but ignores customer-level features, or an ML model like XGBoost that uses every feature available but treats CLV as a generic regression target with no behavioral structure. The probabilistic models are interpretable but leave money on the table. The ML models score better but cannot explain why. The goal was to combine both and prove the hybrid actually earns its complexity.

APPROACH

  • Built a two-stage pipeline on more than 1 million UK e-commerce transactions. Stage one fits BG/NBD + Gamma-Gamma probabilistic models to capture purchase frequency and monetary value distributions. Stage two feeds those probabilistic outputs alongside 23 engineered behavioral features into an Optuna-tuned XGBoost regressor.
  • Engineered features that the probabilistic models miss entirely: purchase velocity trends, category concentration, recency-frequency interaction terms, and inter-purchase interval variability, all designed to capture behavioral signals that distinguish high-value customers from one-time buyers.
  • Built a churn classifier (XGBoost) that improved AUC-ROC by 89 percent over the probabilistic P(alive) baseline, from 0.452 to 0.855 with an F1 of 0.783, by using the same engineered feature set to predict which customers had gone dormant.
  • Discovered 5 behavioral customer segments via K-Means clustering, revealing that 0.3 percent of customers (Whale Accounts) drove disproportionate predicted revenue while 43.5 percent (Lapsed) represented the largest retention opportunity.

WHAT IT FOUND

The hybrid pipeline cut CLV prediction error in half compared to the probabilistic-only baseline: MAE dropped from £673 to £334, with an R² of 0.965 on a 6-month holdout. The improvement was concentrated in the tails, exactly the customers who matter most for campaign targeting: the model separated high-value from low-value customers far more cleanly than either approach alone.

DEPLOYMENT

Deployed a three-page Streamlit dashboard (Portfolio View, Customer Lookup, What-If Simulator) with interactive SHAP waterfall explanations and real-time CLV re-scoring for campaign ROI estimation. Built PSI-based drift monitoring and 19 automated data validation checks into the pipeline, backed by 94 pytest tests. Containerized the full system with Docker Compose, tracked experiments on DagsHub MLflow with XGBoost vs. LightGBM comparison, and versioned all artifacts with DVC.

PROJECT_02 FEATURED

Online experimentation platform simulator

A simulation platform that demonstrates why standard A/B tests break under real-world conditions and implements the sequential and bandit methods that fix them, deployed as an interactive comparison tool.

THE PROBLEM

Most teams run A/B tests by checking results daily and stopping when something looks significant. This is statistically broken: the more you peek, the more you see false positives, because each check is a new opportunity for noise to look like signal. In practice, false positive rates inflate from the nominal 5 percent to 25-30 percent, meaning roughly one in four "winning" variants is actually noise. The platform was built to make this visible and to implement the methods that solve it.

APPROACH

  • Simulated 50K+ e-commerce sessions across multiple test scenarios with configurable effect sizes, traffic volumes, and peek frequencies to demonstrate how repeated significance testing inflates Type I error rates under realistic conditions.
  • Implemented mSPRT sequential testing (mixture sequential probability ratio test), which constructs valid confidence sequences that hold at any stopping time, letting teams check results whenever they want without inflating error rates.
  • Built a Thompson Sampling multi-armed bandit that dynamically routes traffic based on posterior conversion distributions, allocating 85+ percent of traffic to the winning variant in real time and reducing exposure to underperforming treatments compared to fixed 50/50 splits.
  • Added Benjamini-Hochberg multiple testing correction to control false discovery rates when measuring 4+ metrics simultaneously, with automated guardrail alerts that flag variants degrading bounce rate or page load time even when conversion improves.

WHAT IT SHOWS

The platform puts three approaches side by side: classical frequentist (fixed-horizon), sequential (mSPRT), and bandit (Thompson Sampling). Users can watch in real time how the frequentist approach generates false alarms under peeking, how the sequential method maintains valid error rates at any stopping point, and how the bandit minimizes regret by shifting traffic dynamically. The comparison makes the tradeoffs concrete: frequentist is simplest but fragile, sequential is safe but still splits traffic evenly, and bandit optimizes allocation but requires more infrastructure.

DEPLOYMENT

Deployed as an interactive Streamlit dashboard on Streamlit Cloud with conversion curves, confidence intervals, a sample size calculator, and guardrail monitoring panels. The platform compares all three testing approaches in a single view. Backed by 108 automated tests covering simulation logic, statistical calculations, and edge cases.
